# Descobertas técnicas — acesso aos 4 sites (11/10/2026)

## Regra número 1: HTTP só pelo `curl.exe` do Windows
- `C:\Windows\System32\curl.exe` (8.13, Schannel) → **200** na glue-api do VivaReal.
- `Invoke-WebRequest`, `Invoke-RestMethod`, `HttpClient` (.NET) → **403 Cloudflare** na mesma URL, mesmo com User-Agent de Chrome. É a impressão digital TLS do .NET que é barrada.
- Edge/Chrome headless (`--dump-dom`) → bloqueado pelo Cloudflare nas páginas HTML do VivaReal/Zap ("Attention Required").
- Portanto: nos scripts PowerShell, chamar `& "$env:SystemRoot\System32\curl.exe"` com `-s -A "<UA de Chrome>"` e ler a saída. Para JSON grande, usar `System.Web.Script.Serialization.JavaScriptSerializer` com `MaxJsonLength = [int]::MaxValue` (o `ConvertFrom-Json` do PS 5.1 trava em ~2 MB).
- User-Agent usado nos testes: `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/130.0.0.0 Safari/537.36`.

## 1. VivaReal e Zap Imóveis = mesmo banco (Grupo OLX)
API: `https://glue-api.vivareal.com/v2/listings` com header obrigatório `x-domain: www.vivareal.com.br`.
- Com `x-domain: www.zapimoveis.com.br` na **mesma** URL (host vivareal) também responde 200 e devolve os **mesmos anúncios e o mesmo totalCount** (Ipanema 416, Leblon 118, Copacabana 2911 nos critérios). O host `glue-api.zapimoveis.com.br` está atrás do Cloudflare e bloqueia (403). Conclusão: **uma coleta cobre os dois portais**. O `link.href` devolvido muda conforme o x-domain (vivareal ou zap) — para ter o link do Zap, repetir a chamada só com `includeFields=search(result(listings(listing(id),link)))` e x-domain zap, ou montar o link.
- Parâmetros que funcionam (query string):
  `addressNeighborhood=Ipanema&addressState=Rio%20de%20Janeiro&addressCity=Rio%20de%20Janeiro&addressZone=Zona%20Sul&addressType=neighborhood&business=SALE&categoryPage=RESULT&listingType=USED&priceMin=500000&priceMax=1100000&usableAreasMin=35&usableAreasMax=70&unitTypes=APARTMENT&usageTypes=RESIDENTIAL&from=0&size=30&includeFields=...`
  - `addressStreet=Rua%20Francisco%20Otaviano&addressType=street` (com `addressNeighborhood=Copacabana`) funciona: busca por rua (Francisco Otaviano deu 8).
  - `addressStreetNumber` é ignorado. `ids=`, `listingId=`, `q=` são ignorados. **`id=<id>` funciona** (`listings?id=2915533435&includeFields=search(result(listings(listing(id,status,updatedAt,pricingInfos))),totalCount)` → o anúncio com `status:"ACTIVE"`). `externalId=<id>` também. É a checagem de disponibilidade.
  - Busca geográfica (`addressPointLat/Lon`, `viewport`) **não filtra** (devolve a cidade inteira, 12060). Filtrar polígono localmente.
  - `unitTypes` aceita lista separada por vírgula (`APARTMENT,KITNET`? — testar; o site usa `unitTypes=APARTMENT&unitTypesV3=APARTMENT`). Kitnet/studio no VivaReal é `unitTypes=KITNET` (confirmar o totalCount).
- Paginação: **`size` máximo 30** (36+ → HTTP 400). `from` funciona até ~1000 (from=990 ok; from=1500 → 404). Logo, consulta com totalCount > ~1000 precisa ser **fatiada** (faixas de preço, ex.: 500–650k, 650–800k, 800–950k, 950k–1,1M; subdividir até cada fatia < 900) ou feita **por rua**.
- `includeFields` válidos (testados um a um, todos 200): dentro de `listing(...)`: `id,title,address,pricingInfos,usableAreas,totalAreas,bedrooms,bathrooms,suites,parkingSpaces,unitFloor,updatedAt,createdAt,status,publicationType,portal,portals,amenities,description,listingType,usageTypes,unitTypes,advertiserContact,externalId,legacyId,displayAddressType`. No nível de `listings(...)`: `listing(...)`, `account(name,id,licenseNumber,logoUrl)`, `medias`, `link`. Fora: `totalCount`. Pedir **só o necessário** (medias deixa a resposta enorme).
- Formato do anúncio: `address{street,streetNumber,zipCode,neighborhood,zone,point{lat,lon,source,approximateLat,approximateLon},precision:"ROOFTOP",confidence:"VALID_STREET"}`, `pricingInfos:[{businessType:"SALE",price,monthlyCondoFee,yearlyIptu}]` (**IPTU anual**), `usableAreas:[38]`, `bedrooms:[]` (array, pode vir vazio), `parkingSpaces:[]`, `createdAt`, `updatedAt` (ISO), `status:"ACTIVE"`, `publicationType:"SUPER_PREMIUM"|"PREMIUM"|"STANDARD"`. Alguns anúncios vêm só com `approximateLat/approximateLon` (coordenada aproximada) e sem `streetNumber` → tratar como precisão "aproximada".
- Link do anúncio no site: `https://www.vivareal.com.br/imovel/<slug>-id-<id>/` (página HTML bloqueada para robôs, mas o link serve para o Guilherme). Usar o `link.href` da API quando possível.

### 1.1 O que o coletor descobriu a mais (11/10/2026, `Skills\scripts\coletar-vivareal.ps1`; detalhes em `_trabalho/relatorios/vivareal.md`)
- **Filtro de tipo só vale com `unitTypes` + `unitTypesV3` + `unitSubTypes` juntos** (sem `unitSubTypes` a API devolve salas/lojas misturadas; por isso os 416/118/2911 acima caíram para 203/93/2507). `KITNET` na lista devolve 0: kitnets/studios vêm como `APARTMENT` (classificados pelo `unitSubTypes`/título).
- **`categoryPage=RESULT` deduplica** anúncios do mesmo imóvel publicados por filiais da mesma rede (Invicta Botafogo/Copacabana/Leme…), mas o **id representante muda entre rodadas**: em 6 h, 254 de 2.861 ids (8,9 %) saíram do resultado e 258 entraram; 251 dos 254 continuavam `ACTIVE` com o mesmo preço/área (o "irmão" com outro id estava no CSV novo). Sem `categoryPage` o totalCount mais que dobra (Ipanema 475, Leblon 182, Copacabana 4.520) com ids estáveis e o filtro de tipo intacto (Leblon: 182 ids, todos APARTMENT/RESIDENTIAL, 127 imóveis distintos por rua+nº+área+preço). **Decisão (Guilherme, 11/10): o coletor roda SEM `categoryPage` por padrão** ("uma linha por anúncio, com marcação de possível duplicata"; `-DedupApi` restaura o modo antigo). Coleta r3: 5.177 linhas (Ipanema 475, Leblon 182, Copacabana 4.520), 0 descartes, 711 chamadas, 45 MB, 13 min; irmãos pela regra do consolidador (rua+nº ou CEP, área ±2 m², preço ±2 %): Ipanema 475 → 227 imóveis distintos, Leblon 182 → 121. Como sem `categoryPage` o `link` não vem (e `page` dá 500), os links saem num passo próprio por lote de ids com `categoryPage=RESULT` + `page` — includeFields diferentes para VivaReal e Zap, porque a API guarda o `page` em cache pela URL ignorando o x-domain.
- `categoryPage=RESULT` **apaga `title`, `description`, `updatedAt`, `iptuPeriod`** da resposta; esses vêm pela consulta por lote de ids (`listings?id=a,b,c&size=30`, sem categoryPage). **`link` só vem com `page` no includeFields** (busca por bairro); na **consulta por id, `page` derruba a API (HTTP 500)** — por id não há `link`, só `portals` (`OLX,VIVAREAL,ZAP`).
- **IPTU**: `yearlyIptu` e `iptu` trazem o mesmo valor cru; a base vem só do rótulo `iptuPeriod` (MONTHLY/YEARLY/Period_NONE), pouco confiável (394 de 1.189 YEARLY com valor ≤ 300; 33 de 1.558 MONTHLY com valor > 700). O coletor usa a regra pelo valor (`iptu_limite_mensal` = 700 em criterios.json, como no Chaves na Mão) e guarda o rótulo em `iptu_informado`.
- A API **deixa passar área fora do pedido** (40 de 2.905 com 29–34 m² ou 80 m²): reconferência local obrigatória. Bordas de preço **inclusivas** (`priceMin=priceMax=650000` → 158; 650001 → 0). A soma dos totalCounts das fatias de Copacabana (2.610) passa do totalCount do bairro (2.507): a dedup é diferente em faixas largas; o dedup por id resolve.
- `sort=createdAt ASC` estabiliza a paginação; com ele, obtidos = totalCount em todas as faixas (2 coletas ao vivo).

### 3.1 O que o coletor descobriu a mais (11/10/2026, `Skills\scripts\coletar-chavesnamao.ps1`)

  - **IPTU nas descrições — o campo `iptuValue` do site é quase sempre o anual, mesmo quando a descrição fala em "mensal"**: "IPTU mensal R$ 105,30" com o site mostrando R$ 1.053 (= 10 cotas), "IPTU mensal de R$ 260,00 (R$ 2.600,00/ano)" com o site mostrando 2.600. E "Condomínio: R$ 1.006/mês IPTU: R$ 1.580/ano" fazia o regex antigo ler o "/mês" do condomínio como base do IPTU. A regra nova casa os números da descrição com o valor do site (igual → a base que acompanha o número; cota × 10 ou × 12 = valor do site → anual; anual ÷ 10 ou ÷ 12 = valor do site → mensal), lê a janela só a partir de "IPTU" (parando em "Condom"), e só então cai na base por palavra-chave e no limite R$ 700. Nos 581 anúncios da rodada, todos os valores com base explícita "anual" ficaram ≥ 1.053 e todos os "mensal" ≤ 330 — o limite 700 está no vão.
## 4. Mapa / geocodificação
- **Overpass** (`https://overpass-api.de/api/interpreter`, POST com `--data-urlencode 'data=...'`) funciona; a saída é JSON **indentado** (`"type": "way"` com espaço). Ex.: `way["highway"]["name"="Rua Barão da Torre"](-23.0,-43.25,-22.95,-43.15);out geom;`. Instâncias alternativas (kumi, private.coffee) deram 200 vazio ou 500 — usar a principal, com paciência (504 ocasional → tentar de novo).
- **Nominatim** (`https://nominatim.openstreetmap.org/search?format=json&polygon_geojson=1&q=...`, 1 requisição/s, User-Agent próprio) funciona e devolve a geometria (LineString) da via.
- **ViaCEP** (`https://viacep.com.br/ws/22410002/json/`) funciona (CEP → logradouro + complemento com a faixa de números).

## 6. Excel COM (gerar-planilha.ps1) — além do catálogo da memória `feedback_excel_com_powershell_ptbr`
Testado em 11/10/2026 (detalhes em `_trabalho/relatorios/gerar-planilha.md`):
- **"Histórico" é nome reservado de aba** no Excel pt-BR → a aba é `HISTÓRICO RODADAS`.
- **Função que devolve array 2D: `return ,$arr`** (sem vírgula, desenrola em lista plana e `[i, j]` devolve vazio). E **`@(função)` embrulha** o array num elemento só — atribuir direto.
- **Valor saído de `Sort-Object`/`Select-Object` vem embrulhado em PSObject** → `Value2` falha com `0x800A03EC`. Desembrulhar (`.PSObject.BaseObject`) antes de pôr no array 2D.
- **`CopyPicture` + `Chart.Paste` + `Export` só gera imagem com `ScreenUpdating = $true`** (desligado: PNG de 2,7 KB em branco, sem erro). Entre exportações seguidas, pausa de 0,3 s e repetir se o PNG sair < 10 KB.
- **xlsx recém-gravado fica travado por alguns segundos** (Excel fechando / antivírus): esperar a liberação (`File.Open` com `FileShare.None`) antes de abrir ou salvar; se o script morrer com o workbook aberto, o EXCEL.EXE invisível fica órfão segurando o arquivo.
- `=HYPERLINK("url","texto")` escrito via `.Formula` (nome em inglês) funciona em pt-BR e dá link clicável sem `Hyperlinks.Add` célula a célula; `Range.AutoFilter(1)` liga o autofiltro; `Windows.Item(1).SplitRow/SplitColumn/FreezePanes` funciona com Excel invisível (como na memória).
